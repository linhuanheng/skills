# 经济金融学文献整理总结工具

本 skill 帮助用户系统化整理、总结和分析经济金融学领域的学术文献，生成高质量文献综述文档，支持文献对比分析和结构化整理。

## 核心原则

### 1. 文献分析导向
- **结构化整理**：按研究主题、方法、结论等维度系统整理文献
- **批判性分析**：不仅总结文献内容，更关注文献之间的逻辑关系和研究脉络
- **学术严谨性**：确保文献综述的学术标准和引用规范

### 2. 多维度分析
1. **主题归类**：按研究主题和子领域分类文献
2. **方法学分析**：分析文献采用的理论模型、实证方法和数据来源
3. **结论对比**：对比不同文献的主要发现和结论
4. **研究脉络**：梳理研究领域的发展脉络和趋势
5. **摘要与引言深度分析**：系统分析文献摘要和引言的核心要素（研究主题、问题定位、工作内容、边际贡献、核心观点、研究背景、文献基础、研究目标）

## 核心原则（详细）

1. **系统性**：文献整理应全面系统，避免选择性引用
2. **逻辑性**：文献综述应有清晰的逻辑结构和论证脉络
3. **批判性**：对文献的优缺点、局限性进行分析评价
4. **规范性**：遵循学术文献综述的写作规范和引用格式
5. **实用性**：为后续研究提供有价值的文献基础和方向指引

## 技能功能

### 基础功能

#### 1. 文献结构化整理
- **文献信息收集**：整理文献的基本信息（作者、年份、期刊、关键词等）
- **主题分类**：按经济金融子领域（宏观、微观、计量、金融等）分类文献
- **方法分类**：按研究方法（理论建模、实证分析、实验研究等）分类文献
- **关键概念提取**：提取文献的核心概念、理论框架和重要结论

#### 2. 摘要与引言深度分析（核心功能）
- **摘要结构化分析**：系统分析文献摘要的五个关键要素：
  - **研究主题**：研究领域的归属和具体研究问题
  - **工作内容**：研究方法、数据来源、技术路线
  - **核心观点**：主要研究结论和重要发现
- **引言深度挖掘**：分析引言部分的三个核心内容：
   - **研究主题**：研究领域的归属和具体研究问题
  - **问题定位**：核心研究问题及其学术和实践意义
  - **工作内容**：研究方法、数据来源、技术路线
  - **边际贡献**：理论、实证、方法、政策贡献
  - **核心观点**：主要研究结论和重要发现
  - **研究背景**：现实背景、学术演进脉络、研究重要性
  - **文献基础**：相关文献评述、现有研究的成就与不足
  - **研究目标**：明确的研究目标、预期贡献、基本假设
- **结构化信息记录**：创建详细的文献信息矩阵，包含9个关键维度

#### 3. 文献综述生成
- **综述结构设计**：设计文献综述的逻辑结构
- **研究脉络梳理**：梳理研究领域的发展历史和研究趋势
- **研究空白识别**：识别现有研究的不足和未来研究方向
- **高质量综述撰写**：生成符合学术标准的文献综述文档

#### 4. 文献对比分析
- **观点对比**：对比不同文献的理论观点和政策主张
- **方法对比**：对比不同文献的研究方法和数据来源
- **结论对比**：对比不同文献的实证结果和政策含义
- **学派分析**：分析不同学术流派或研究传统的特点和分歧

#### 5. Zotero 文献库访问（完全依赖 zotero-mcp）
- **MCP 服务器检查**：检查是否已配置并启用 zotero-mcp 服务器
- **文库浏览**：通过 MCP 工具获取并展示可用的 Zotero 文库（收藏夹/集合）
- **文献检索**：**仅**使用 MCP 工具检索指定文库中的文献
- **文献详情获取**：通过 MCP 工具获取单篇文献的完整元数据
- **笔记和标签**：通过 MCP 工具获取文献的笔记和标签信息
- **不支持其他方式**：不提供手动输入、文件导入或数据库直接访问

#### 5. 交互流程管理
- **文库选择交互**：通过 AskUserQuestion 工具让用户选择要整理的特定 Zotero 文库
- **分析维度选择**：根据用户需求选择分析的重点维度
- **输出格式定制**：根据用户需求定制输出文档的格式和深度

#### 6. 全文内容获取（支持深度分析）
- **PDF 全文提取**：优先调用 `mcp__markitdown__convert_to_markdown` 通过 markitdown MCP 服务器解析 PDF 文件，获取高质量的结构化 Markdown 内容。如果 PDF 文件无法通过 markitdown 解析，则回退到调用 zotero-mcp 的 `get_content` 获取文献完整内容。
- **章节识别**：自动识别摘要 (Abstract) 和引言 (Introduction) 部分
- **关键信息抽取**：从摘要和引言中提取研究主题、问题定位、边际贡献等核心要素
- **markitdown 优势**：提供更准确的文本结构识别、数学公式保持（LaTeX格式）、表格保留和智能格式转换

#### 7. 单篇文献详细总结（新增功能）
- **文库选择**：通过 AskUserQuestion 让用户选择要分析的 Zotero 文库（收藏夹/集合）
- **文献选择**：从选定文库中选择单篇文献进行深度分析
- **侧重点确认**：通过 AskUserQuestion 让用户选择分析侧重点（理论框架/实证设计/贡献创新/批判评价/综合分析）
- **全方位解读**：对单篇文献进行全方位、多层次的详细解读
- **结构化解构**：按论文章节结构（摘要、引言、理论、实证、结论）逐部分分析
- **深度评价**：对文献的贡献、局限性、启示进行批判性评价
- **Markdown 输出**：生成单篇文献详细总结的 Markdown 文档并保存到 ./output/[第一作者]_[年份]/ 目录

### 高级功能

## Zotero MCP 服务器交互

### 1. zotero-mcp 服务器说明

zotero-mcp 是一个通过 Model Context Protocol (MCP) 提供 Zotero 访问服务的服务器。本 skill **完全依赖** zotero-mcp 与 Zotero 交互，不使用其他方式。

**服务器配置**：
- **服务器名称**: zotero-mcp
- **传输方式**: HTTP
- **端点**: `http://127.0.0.1:23120/mcp`
- **前提条件**: Zotero 必须正在运行且 MCP 插件服务已启用

### 2. zotero-mcp 配置流程

#### 第一步：添加 zotero-mcp 服务器
使用 Claude Code 的 MCP 命令添加服务器：

```bash
# 仅当前项目可用
claude mcp add --transport http zotero-mcp http://127.0.0.1:23120/mcp

# 全局可用（所有项目）
claude mcp add --transport http --scope user zotero-mcp http://127.0.0.1:23120/mcp
```

#### 第二步：验证配置
```bash
# 查看已添加的 MCP 服务器
claude mcp list

# 查看 zotero-mcp 详情
claude mcp get zotero-mcp
```

#### 第三步：检查 MCP 资源
在 Claude Code 中：
1. 输入 `/mcp` 命令查看 MCP 服务器状态
2. 确认 zotero-mcp 显示为已连接
3. 查看可用的 MCP 工具列表

### 3. MCP 服务器检查流程

#### 检查可用性
使用 `ListMcpResourcesTool` 检查可用的 MCP 资源：

```
1. 调用 ListMcpResourcesTool 获取所有可用的 MCP 资源
2. 检查是否存在 zotero-mcp 相关的资源
3. 如存在，记录可用的工具和资源 URI
```

**情况 A：zotero-mcp 可用**
- 显示可用工具列表
- 继续执行文献整理流程

**情况 B：zotero-mcp 不可用**
- 告知用户未检测到 zotero-mcp 服务器
- 提供配置命令：`claude mcp add --transport http zotero-mcp http://127.0.0.1:23120/mcp`
- 提醒用户确保 Zotero 正在运行
- **无法继续文献整理流程**：本 skill 完全依赖 zotero-mcp

### 4. 故障排除命令

```bash
# 移除并重新添加服务器
claude mcp remove zotero-mcp
claude mcp add --transport http zotero-mcp http://127.0.0.1:23120/mcp

# 检查服务器状态
claude mcp get zotero-mcp
```

### 5. zotero-mcp 可用工具

根据 zotero-mcp 服务器提供的工具，本 skill 可以使用以下功能：

| 工具名 | 功能描述 |
|--------|----------|
| `search_library` | 搜索 Zotero 文库 |
| `get_item_details` | 获取文献详细信息 |
| `get_content` | 获取文献全文内容（包含PDF、附件、笔记等完整内容） |
| `search_fulltext` | 全文搜索 |
| `get_collections` | 获取收藏夹列表 |
| `search_annotations` | 搜索注释和标注 |

**注意**：zotero-mcp 中的工具名是 `get_content`（而不是 `get_item_fulltext`），用于获取文献的完整内容，包括PDF全文、附件内容、笔记等。

### 6. markitdown MCP 服务器支持（新增）

为了获得更高质量的PDF解析结果，本 skill 现在支持使用 markitdown MCP 服务器进行PDF文件解析。markitdown 提供以下优势：

- **结构化解析**：智能识别PDF的章节结构、标题层级
- **数学公式保留**：保持LaTeX格式的数学公式
- **表格转换**：将PDF表格转换为Markdown表格格式
- **格式保持**：保持文本格式（粗体、斜体、代码等）
- **高质量输出**：生成易于分析的Markdown内容

#### 6.1 markitdown MCP 服务器配置

如果用户已配置 markitdown MCP 服务器，本 skill 将优先使用 markitdown 进行PDF解析：

```bash
# 配置 markitdown MCP 服务器
claude mcp add --transport stdio markitdown "npx" "-g" "@modelcontextprotocol/server-markitdown"
```

#### 6.2 PDF 解析优先级策略

在需要获取文献PDF全文内容时，本 skill 按以下优先级执行：

1. **优先**：如果 markitdown MCP 服务器可用且PDF文件可通过 `file://` 或 `http://` 协议访问，调用 `mcp__markitdown__convert_to_markdown` 进行高质量解析
2. **回退**：如果 markitdown 不可用或PDF文件无法访问，调用 zotero-mcp 的 `get_content` 获取文献内容
3. **最终**：如果以上都不可用，仅使用文献元数据和摘要进行分析

#### 6.3 markitdown 兼容性说明

使用 markitdown 解析PDF需要PDF文件的直接访问路径。通常需要通过以下方式：
- 从 Zotero 中导出PDF文件到本地目录
- 通过Zotero的附件链接获取PDF文件路径
- 使用 `file://` 协议的本地文件路径

## 细化文献分析流程框架

### A. 多篇文献综述流程

#### 前置阶段：MCP 检查与需求确认
```
1. 检查 MCP 服务器配置
   a. 调用 ListMcpResourcesTool 检查可用资源
   b. 确认 zotero-mcp 服务器是否可用
   c. 如不可用，提供配置命令，无法继续
2. 确认文献整理的目的（研究综述、研究计划、课程作业等）
3. 确认文献来源：**仅支持 zotero-mcp 访问**
4. 通过 zotero-mcp 获取文库列表并确认选择
5. 确认分析的重点维度和深度要求
6. 确认输出格式和文档结构
7. 确认是否需要获取全文内容进行深度分析
```

### 第一阶段：文献信息收集与预处理（支持 zotero-mcp + markitdown）
```
1. 通过 zotero-mcp 进行信息收集：
   a. 调用 MCP 工具获取文库列表
   b. 用户选择文库
   c. 调用 MCP 工具获取文献列表
   d. 调用 MCP 工具获取文献详情
   **注：不支持手动输入或文件导入**
   
2. 获取文献全文内容（重点，优先级策略）：
   a. **检查 markitdown MCP 可用性**：调用 ListMcpResourcesTool 检查 markitdown 服务器
   b. **优先使用 markitdown**：
      - 如果 markitdown 可用且能从 Zotero 获取 PDF 文件路径（file:// 或 http:// 协议）
      - 调用 `mcp__markitdown__convert_to_markdown` 解析 PDF
      - 获得结构化 Markdown 内容（保持章节、公式、表格）
   c. **回退到 zotero-mcp**：
      - 如果 markitdown 不可用或 PDF 路径无法访问
      - 调用 `get_content` 获取 PDF 全文内容
   d. 如果没有全文，尝试获取其他格式的完整内容
   
3. 提取文献基本信息（作者、年份、标题、期刊、DOI 等）
4. 提取文献摘要、关键词和用户笔记
```

#### markitdown PDF 解析详细流程
```
1. 从 Zotero 获取 PDF 附件信息：
   - 调用 `get_item_details` 获取文献的附件列表
   - 识别 PDF 类型的附件
   - 提取 PDF 文件路径或 URI

2. 使用 markitdown 解析 PDF：
   - 如果 PDF 路径为 file:// 协议：直接调用 `mcp__markitdown__convert_to_markdown(uri="file:///path/to/file.pdf")`
   - 如果 PDF 路径为 http://协议：调用 `mcp__markitdown__convert_to_markdown(uri="http://example.com/file.pdf")`
   - 获取 Markdown 格式的结构化内容

3. 内容后处理：
   - 识别摘要 (Abstract) 部分
   - 识别引言 (Introduction) 部分
   - 识别其他章节结构
   - 提取数学公式（LaTeX 格式）
   - 提取表格（Markdown 表格格式）

4. 解析失败处理：
   - 如果 markitdown 解析失败，回退到 zotero-mcp 的 `get_content`
   - 记录失败原因并提示用户
```

### 第二阶段：摘要与引言深度分析（核心阶段）
```
1. 摘要部分提取与分析（Abstract）：
   a. **研究主题**：研究领域的归属（宏观/微观/计量/金融等）

   c. **工作内容**：主要研究方法、数据来源和样本特征、技术路线
   d. **边际贡献**：相对于现有研究的创新点（理论/实证/方法/政策贡献）

2. 引言部分提取与分析（Introduction）：
   a. **研究背景**：研究问题的现实背景、学术研究演进脉络
   b. **文献评述**：相关文献的梳理、现有研究的成就与不足
   c. **研究目标**：明确的研究目标、预期贡献、基本假设
   
3. 创建结构化文献信息记录表：
   | 字段 | 内容描述 |

   | 研究目标 | 明确的研究目标 |
```

### B. 单篇文献详细总结流程

#### 前置阶段：MCP 检查、文库选择与文献选择
```
1. 检查 MCP 服务器配置（同上）
2. 文库选择：通过 get_collections 获取所有文库，通过 AskUserQuestion 让用户选择要分析的文库
3. 文献选择：通过 get_collection_items 获取选定文库中的所有文献，通过 AskUserQuestion 让用户选择文献
   （或通过 search_library 在选定文库中搜索特定文献）
4. 分析侧重点确认：通过 AskUserQuestion 让用户选择分析侧重点
   - 理论框架与模型：重点分析理论假设、模型设定、命题推导
   - 实证设计与方法：重点分析数据来源、变量定义、识别策略
   - 贡献与创新性：重点分析边际贡献、理论/实证/方法创新
   - 批判性评价：重点分析局限性、假设合理性、改进方向
   - 综合全面分析：涵盖所有维度的全面分析
5. 分析目的确认：文献阅读笔记 / 课程作业 / 研究参考
6. 分析深度确认：标准精读 / 深度研读
7. 输出格式确认：完整总结文档 / 精简笔记 / 分析报告
```

#### 第一阶段：文献信息获取（支持 markitdown PDF 解析）
```
1. 调用 `get_item_details` 获取文献完整元数据
2. 获取 PDF 全文内容（优先级策略）：
   a. 检查 markitdown MCP 服务器可用性
   b. 从 `get_item_details` 结果中提取 PDF 附件路径
   c. 如果 markitdown 可用且 PDF 路径可访问：
      - 调用 `mcp__markitdown__convert_to_markdown` 解析 PDF
      - 获得结构化 Markdown 内容（保持章节、公式、表格）
   d. 如果 markitdown 不可用或 PDF 路径无法访问：
      - 调用 `get_content` 获取 PDF 全文内容
3. 调用 `search_annotations` 获取用户标注和笔记
4. 提取文献所有章节结构
```

#### 第二阶段：根据侧重点的逐章节深度分析
```
1. 摘要分析（五要素）（所有侧重点均需分析）：
   - 研究主题、问题定位、工作内容、边际贡献、核心观点

2. 引言分析（三要素）（所有侧重点均需分析）：
   - 研究背景、文献基础、研究目标

3. 理论框架分析（根据侧重点调整深度）：
   - 基本假设、模型设定、命题/假说、作用机制
   - *侧重点为"理论框架与模型"时：深度分析假设合理性、模型推导、命题证明
   - *侧重点为"贡献与创新性"时：重点分析理论贡献和创新点
   - *侧重点为"批判性评价"时：重点分析理论假设的局限性和改进方向

4. 实证设计分析（如实证论文）（根据侧重点调整深度）：
   - 数据来源、变量定义、模型设定、识别策略
   - *侧重点为"实证设计与方法"时：深度分析数据质量、变量构造、识别策略有效性
   - *侧重点为"贡献与创新性"时：重点分析实证方法创新和数据创新
   - *侧重点为"批判性评价"时：重点分析实证设计的局限性和内生性问题

5. 实证结果分析（如实证论文）（根据侧重点调整深度）：
   - 基准回归、稳健性检验、异质性分析、机制检验
   - *侧重点为"实证设计与方法"时：深入分析结果的经济学解释和统计意义
   - *侧重点为"批判性评价"时：分析结果的稳健性和潜在问题

6. 结论与讨论分析（所有侧重点均需分析）：
   - 主要结论、政策建议、研究局限、未来方向
   - *侧重点为"批判性评价"时：深入分析局限性和改进建议
```

#### 第三阶段：综合评价
```
1. 学术贡献评价：
   - 理论贡献、实证贡献、方法贡献、政策贡献

2. 局限性分析：
   - 数据局限、方法局限、假设局限

3. 启示与拓展：
   - 对未来研究的启示
   - 可能的拓展方向
```

#### 第四阶段：Markdown 文件生成与保存
```
1. 按照单篇文献总结模板组织内容
2. 生成结构化的 Markdown 文档
3. 保存至 ./output/[第一作者]_[年份]_[关键词]/
4. 文件命名：[第一作者]_[年份]_[文献标题关键词]_详细总结.md
```

### Markdown 格式规范

1. **标题层级**：
   - H1 (`#`): 文档标题
   - H2 (`##`): 主要章节
   - H3 (`###`): 子章节
   - H4 (`####`): 细分子章节

2. **强调格式**：
   - 粗体 (`**text**`): 关键术语、重要概念
   - 斜体 (`*text*`): 外文词汇、特殊强调
   - 删除线 (`~~text~~`): 不推荐使用

3. **列表格式**：
   - 无序列表 (`-` 或 `*`)
   - 有序列表 (`1.` `2.` `3.`)

4. **表格格式**：
   ```markdown
   | 列 1 | 列 2 | 列 3 |
   |------|------|------|
   | 内容 | 内容 | 内容 |
   ```

5. **引用格式**：
   - 块引用 (`>`)
   - 脚注 (`[^1]`)

6. **代码块**（如需要）：
   \`\`\`[语言]
   [代码内容]
   \`\`\`

7. **分隔线**：
   - 使用 `---` 分隔主要章节

8. **参考文献格式**：
   ```markdown
   [1] Author, A. (Year). Title of the article. *Journal Name*, Volume(Issue), pages.
   ```

## 交互流程示例

### 示例 1：研究主题文献综述（使用 zotero-mcp）

**用户**："我想了解关于经济增长收敛理论的文献，生成一份综述"

**Skill 交互流程**:
1. **MCP 检查**：
   - 调用 ListMcpResourcesTool 检查 zotero-mcp 可用性
   - 确认可用后继续
2. **文库选择**：
   - 调用 `get_collections` 获取收藏夹列表
   - 用户选择相关收藏夹（如"经济增长"）
3. **文献获取**：
   - 调用 `search_library` 获取文献列表
   - 调用 `get_item_details` 获取每篇文献详情
   - 调用 `get_content` 获取文献全文内容（用于摘要和引言分析）
4. **需求确认**：使用 AskUserQuestion 确认综述目的、时间范围、深度要求
5. **摘要与引言深度分析**（核心阶段）：
   - 对每篇文献进行摘要五要素分析：
     - **研究主题**：识别文献所属领域（经济增长理论）
     - **问题定位**：提取收敛理论要解决的核心问题
     - **工作内容**：整理了作者使用的理论模型和实证方法
     - **边际贡献**：识别了文献的理论创新点和实证贡献
     - **核心观点**：总结了主要研究结论
   - 对每篇文献进行引言三要素分析：
     - **研究背景**：理解了研究的现实背景和学术脉络
     - **文献基础**：掌握了作者对相关文献的评述
     - **研究目标**：明确了作者的研究目标和预期贡献
6. **主题分类**：按经济增长收敛的不同理论框架分类文献
   - 绝对收敛理论
   - 条件收敛理论
   - 俱乐部收敛理论
   - 非线性收敛理论
7. **深度分析**：
   - 分析不同理论的基本假设和预测
   - 对比不同理论的实证检验方法
   - 评估理论的政策含义
8. **综述生成**：生成包含以下内容的综述文档
   - 经济增长收敛理论的发展脉络
   - 主要理论模型的比较分析
   - 实证研究的进展和挑战
   - 未来研究方向和政策启示

## 故障排除

### 常见问题

#### 1. zotero-mcp 服务器不可用
**症状**：`/mcp` 命令未显示 zotero-mcp 服务器或 ListMcpResourcesTool 未返回相关资源

**解决方案**：
1. 确保 Zotero 正在运行
2. 确保 Zotero MCP 插件服务已启用
3. 检查是否已添加服务器配置：
   ```bash
   claude mcp list
   ```
4. 如未添加，执行配置命令：
   ```bash
   claude mcp add --transport http zotero-mcp http://127.0.0.1:23120/mcp
   ```
5. 添加后无需重启 Claude Code，直接重试

#### 2. MCP 工具调用失败
**症状**：调用 zotero-mcp 工具时返回错误

**解决方案**：
- 确认 Zotero 正在运行
- 检查 zotero-mcp 服务是否在端口 23120 运行
- 检查防火墙设置，确保允许本地连接
- 使用以下命令验证配置：
  ```bash
  claude mcp get zotero-mcp
  ```
- 尝试调用其他 MCP 工具确认服务器状态

#### 3. 配置问题
**症状**：添加服务器后仍然无法连接

**解决方案**：
- 移除并重新添加服务器：
  ```bash
  claude mcp remove zotero-mcp
  claude mcp add --transport http zotero-mcp http://127.0.0.1:23120/mcp
  ```
- 检查 Zotero 插件是否正确安装并启用
- 确认插件的 HTTP 服务已启动

#### 4. 文献获取不完整
**症状**：获取的文献数量少于预期

**解决方案**：
- 确认选择的收藏夹是否包含子收藏夹
- 检查是否有文献筛选条件限制
- 尝试搜索关键词获取相关文献
- 考虑选择多个相关收藏夹

#### 5. 文献选择偏差
**症状**：综述偏向特定观点或方法，缺乏全面性

**解决方案**：
- 扩大文献搜索范围，涵盖不同学术传统
- 有意识地包括不同观点和方法的文献
- 寻求领域专家的建议和补充

#### 6. 分类混乱
**症状**：分类标准不清晰，文献分类重叠或遗漏

**解决方案**：
- 明确分类的维度和标准
- 确保分类之间的互斥性和完备性
- 提供分类标准的详细说明

#### 7. 缺乏批判性
**症状**：综述变成文献罗列，缺乏分析和评价

**解决方案**：
- 加强文献之间的对比分析
- 关注研究方法的优缺点评估
- 分析研究结论的稳健性和局限性

#### 8. 结构混乱
**症状**：综述逻辑不清晰，各部分衔接不自然

**解决方案**：
- 提前设计清晰的综述结构
- 确保各部分之间的逻辑连贯性
- 使用过渡段落和主题句增强连贯性

#### 9. Markdown 文件保存失败
**症状**：文件保存时出错或保存后无法找到文件

**解决方案**：
- 检查输出目录是否存在，如不存在则创建
- 确认文件路径是否有效（避免非法字符）
- 检查是否有写入权限
- 使用绝对路径保存文件
- 保存后验证文件是否存在

#### 10. Markdown 格式问题
**症状**：生成的 Markdown 文件在某些平台渲染不正确

**解决方案**：
- 使用标准 Markdown 语法，避免使用特定平台的扩展语法
- 表格使用 GitHub 兼容格式
- 确保标题层级正确（H1 → H2 → H3）
- 检查特殊字符是否正确转义

#### 11. 单篇文献总结内容不完整
**症状**：单篇文献总结缺少某些章节的分析

**解决方案**：
- 检查 PDF 全文是否完整提取
- 确认论文章节结构识别正确
- 对于缺失的章节， manually 标注需要重点分析的部分
- 重新调用分析流程补充缺失内容

#### 12. 文献选择不当
**症状**：选择的文献不重要或不相关

**解决方案**：
- 优先选择顶刊和高被引文献
- 通过关键词搜索筛选相关文献
- 参考文献引用网络找到核心文献
- 咨询导师或同行的建议

## 重要提示

**本 skill 专注于文献分析和综述写作**：
- 不进行原始数据收集和实证分析
- 不替代学术判断和独立思考
- 需要用户提供或确认文献信息
- 输出文档需要用户进一步审核和完善

**本 skill 的价值在于**：
- 系统化整理文献信息
- 提供分析框架和思路
- 生成初步的文献综述草稿
- 识别研究空白和未来方向
- 通过 zotero-mcp 简化 Zotero 访问流程
- **细化文献分析**：通过摘要和引言深度分析，精准提取文献的核心要素
- **结构化信息矩阵**：构建包含 9 个维度的文献信息记录表，确保分析全面性
- **高质量综述生成**：基于深度分析生成更精准、更深入的文献综述
- **Markdown 文件保存**：自动生成格式规范、结构完整的 Markdown 文档，便于分享和版本管理

**zotero-mcp 是使用 Zotero 功能的必要条件**：
- 本 skill **完全依赖** zotero-mcp 与 Zotero 交互
- 不直接访问 Zotero 数据库或 SQLite 文件
- 不提供手动导出、文件导入等替代方案
- 使用 zotero-mcp 前需确保服务器正确配置
- 如 zotero-mcp 不可用，无法使用本 skill 的 Zotero 功能

**用户的责任在于**：
- 配置 zotero-mcp 服务器：`claude mcp add --transport http zotero-mcp http://127.0.0.1:23120/mcp`
- 确保 Zotero 正在运行
- 提供准确全面的文献信息
- 验证分析结果的准确性
- 完善和深化分析内容
- 确保最终文档的学术质量
